# P0-3: real Qwen TPR P512/S512 vs Native CP1 and Native CP2

## Why

P0-2A on real Qwen layer1 held X/W/dY fixed and showed small local
BF16 GEMM M effects:
- Y relative L2: 1.7e-5 to 3.4e-5;
- dX relative L2: 2.3e-5 to 4.3e-5;
- dW relative L2: ~0.22%-0.23% (diagnostic FP32 SUM) or
  ~0.28%-0.36% (BF16 SUM).

P0-2B (user NPU, 2026-10-11) held REAL Q/K/V/dO fixed and ran native
CP1 full and CP2/CP4 Ring attention at layer1:

| Metric rel L2 | Native CP2 / CP1 | Native CP4 / CP1 |
|---|---:|---:|
| Attention output O | 0.00237167166 | 0.00310345189 |
| dQ | 0.0228869934 | 0.028170538 |
| dK | 0.00371157992 | 0.0044391392 |
| dV | 0.00192651613 | 0.00263110459 |

CP1 actual-vs-independent-replay was essentially exact:
O=0, dQ=5.4e-8, dK=2.25e-7, dV=1.63e-9.
One-layer native Ring changes Attention numerics more than one fixed
GEMM M change, but comparisons are of different tensors, and neither
alone establishes the full-model CP1/2 logprob drift's root cause.
**TPR correctness is a distinct question**.

## Four comparable executions, one actual real TQ row

Use exactly the P0-1 real TQ source:
`row0: prompt_tail512 + response_head512`, 1024 real tokens,
all 512 response next-token targets, *including the query at global
position 511 predicting response token 0*.

1. **Native CP1 Full**: unmodified Megatron/MindSpeed full GPT;
   previously saved `/tmp/tpr_p0_native_cp/native_cp1.pt`.
2. **Native CP2 Full**: unmodified MindSpeed Ring, official CP2
   Zigzag, each rank owns `[256 contiguous early tokens, 256 contiguous
   late tokens]`; previous `native_cp2.pt`.
3. **TPR-controlled Full CP1**: pretrained same Megatron TPR-model
   weights, no active TPR context, one complete 1024-token forward
   and backward (the fixture uses its controlled CANN core).
4. **TPR P512/S512 CP1**: SAME model instance / initial weights,
   true `SegmentExecutor` (not a mock):
   `push(prefix512) → visit_leaf(suffix512) → pop(prefix512)`,
   external-KV rectangular Attention and 28-layer KV gradient relay.
   The 512 response logprobs are emitted by physical owner:
   Prefix-last-query (1) + Suffix-query0..510 (511).

The TPR executor loss callback and native CP1/2 oracle use the **same
F.log_softmax + gather /512 objective**; all 512 real response tokens
are supervised. This aligns with P0-1, not Stage B's masked-window NLL.

**CRITICAL LIMITATION:** Native CP2's physical Linear M=512 and TPR's
Prefix512/Suffix512 each have M=512, BUT the native CP2 per-rank
sequence chunks are **noncontiguous 256+256 Zigzag**, and its Ring
Attention differs from TPR's contiguous-prefix KV reuse.
Do not call CP2 a mathematically same-kernel TPR oracle.

The comparator reports these diagnostic pairs:
- TPR-controlled Full → TPR P512/S512 (**primary TPR execution delta**)
- Native CP1 → TPR-controlled Full (**attention/reference floor**)
- Native CP1 → Native CP2 (**previous validated CP baseline**)
- Native CP1 → TPR P512/S512 (**end-to-end practical reference gap**)
- Native CP2 → TPR P512/S512 (**matched M=512, not matched execution**)

For every pair record response logprob mean/max/p95, relative L2,
cosine, loss delta, and per-parameter **strided sampled BF16 gradient**
relative L2/cosine and the worst parameter names. There are no invented
numerical acceptance thresholds, no artificial FP32 GEMM, no padding,
and no optimizer updates in P0-3.
